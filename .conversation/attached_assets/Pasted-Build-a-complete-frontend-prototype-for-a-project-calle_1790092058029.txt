Build a complete frontend prototype for a project called **FarmIQ – Smart Procurement Scheduling for Farmers**.

## PURPOSE

FarmIQ is a simple farmer-friendly web application that helps farmers know:

- When and where they can sell their crops
- Available procurement schedules
- Their assigned time slot
- Their digital token number
- Current queue position
- Estimated waiting time
- Procurement status and updates

The goal is to reduce unnecessary waiting, uncertainty and missed procurement opportunities.

## IMPORTANT DESIGN DIRECTION

Do NOT make this look like a futuristic AI startup, crypto dashboard, or high-tech SaaS product.

The interface should feel like a **modern but simple Indian government/public-service website**, designed specifically for farmers.

Think:

- Simple
- Trustworthy
- Clean
- Familiar
- Easy to understand
- Large buttons
- Large readable text
- Minimal technical terminology
- Clear icons
- Simple navigation
- Mobile-friendly
- Accessible to people who may not be very comfortable with technology

The user should immediately understand what to do without needing instructions.

Use a calm agricultural/public-service visual style.

Avoid:
- Neon colors
- Glassmorphism
- Excessive gradients
- Dark futuristic UI
- Complicated charts
- Tiny text
- Excessive animations
- Cryptocurrency/SaaS-style dashboards
- Overly sophisticated AI visuals

## TECHNOLOGY

Use ONLY:

- HTML
- CSS
- JavaScript
- React

Use React components properly.

Create a clean Vite-compatible React project.

Do not use backend functionality. This is a frontend prototype, so use realistic mock data and local React state where necessary.

## LANGUAGE

For the prototype, use **simple English**, but structure the UI so that Kannada/Hindi/regional-language support could easily be added later.

Include a visible **Language** selector in the header, for example:

English
ಕನ್ನಡ
हिंदी

It does not need to actually translate everything yet.

## MAIN USER FLOW

Design the application around this simple farmer journey:

1. Farmer opens FarmIQ
2. Farmer registers/selects their crop
3. Farmer enters location and quantity
4. FarmIQ shows suitable procurement centres
5. Farmer selects a centre
6. Farmer receives a time slot and digital token
7. Farmer can track their queue
8. Farmer receives alerts/reminders
9. Farmer sees procurement status

## INTERACTIVITY

Even though there is no backend, make the prototype feel functional.

For example:

- Registration form should move to the next screen
- Crop selection should update the displayed crop
- Procurement centre selection should open available slots
- Slot selection should generate/display a mock token
- Queue page should display the selected token
- Navigation should work
- Buttons should have appropriate hover/tap states
- Use React state for temporary data

Do NOT create fake API calls or pretend that real AI/backend systems are connected.

## AI REPRESENTATION

FarmIQ is described as AI-powered, but do not overuse the word "AI" throughout the interface.

The farmer doesn't need to understand the AI.

Instead of:

"AI-powered predictive procurement optimization engine"

simply say:

"FarmIQ helps you find a suitable time slot."

The technical AI functionality can be shown later in an admin/technical section.

## FINAL RESULT

The finished prototype should feel like:

**A simple government agricultural service that a normal farmer can understand within 10 seconds.**

It should NOT feel like:

**A futuristic AI startup dashboard.**

Prioritize usability and clarity over visual complexity.

Build all the screens above and make the navigation between them functional using React state/routing.
